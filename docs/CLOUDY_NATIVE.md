# Cloudy 네이티브 렌더러

과거 원화·버전·백업의 이동 위치와 복구 방법은 [Cloudy 작업 자료 보관](CLOUDY_ARCHIVE.md)에 기록했습니다. 현재 실행·미리보기·비교 검증에 필요한 파일은 원래 위치에 유지합니다.

현재 앱은 `assets_cloudy_rig_v4/directional_v5`의 **실제 디스크 v30** 원화와 동작 계산을 Qt OpenGL 화면에 그립니다. 기존 캐릭터 창의 이동·드래그·대화 기능은 유지하고, 렌더링을 `CloudyRigView`로 연결했습니다. 감정, 동작, 바라보는 방향, 실제 음성 재생은 각각 독립된 상태입니다.

실시간 네이티브 화면은 **30fps를 목표**로 갱신하며, 원본 동작의 진행 시간은 단조 시계로 유지합니다. 아래의 PNG 검증 20fps와 파일 크기를 줄인 GIF 미리보기 10fps는 증거 자료의 샘플링 속도입니다.

이 문서의 기준은 v30입니다. 예전 미리보기 URL에 남은 `rollback=v22` 쿼리는 v22 파일을 선택하는 기능이 아니며, 그 URL도 현재 파일을 읽습니다. v22 캡처는 이전 작업의 역사적 자료입니다. 이번 일치 검증에는 [v30 원본 WebGL 캡처](../assets_cloudy_rig_v4/directional_v5/validation-left-elbow-v30/final-full/capture-metadata.json)를 사용했습니다.

## 실행과 기존 화면으로 전환

프로젝트 루트의 PowerShell에서 실행합니다.

```powershell
$env:CLOUDY_RENDERER = 'rig'
.\.venv\Scripts\python.exe main.py
```

캐릭터 우클릭 메뉴의 **캐릭터 동작**에서 인사·생각·수면·대기 동작과 왼쪽·정면·오른쪽 방향을 선택할 수 있습니다. 감정 변화가 걷기나 인사의 시간을 다시 시작하지 않습니다. 대화 입 모양은 텍스트 요청이나 합성 시작이 아니라 `QAudioSink`의 실제 재생 상태를 따라갑니다.

기존 PNG 재생 화면으로 실행하려면 다음과 같이 선택합니다.

```powershell
$env:CLOUDY_RENDERER = 'sprite'
.\.venv\Scripts\python.exe main.py
```

네이티브 초기화나 실행 중 렌더링이 실패하면 앱은 기존 PNG 재생으로 전환합니다. 실제 런타임은 PyQt6 OpenGL과 별도 Node/V8 작업 프로세스를 사용합니다. Node는 `CLOUDY_NODE` 지정 경로, PATH, 이 컴퓨터의 Codex 번들 경로 순서로 찾습니다. 다른 컴퓨터에서는 Node 설치 또는 `CLOUDY_NODE` 설정이 필요합니다.

## 원본 보존과 계산 일치

원본 JS와 PNG 파일을 수정하지 않고 동작 계획을 읽습니다. Node 작업 프로세스는 원래 JS를 실행하고 Float32 정점과 재질 정보를 전달하며, Qt가 실제 GPU 텍스처를 관리합니다. QJSEngine 구현은 비교 검증에 사용되며 현재 화면의 실행 엔진은 Node/V8입니다.

[플래너 검증 테스트](../tests/test_rig_planner.py) **127개 통과**를 확인했습니다. 그 안에는 3방향 × 9동작의 27개 계획과 3방향 × 15감정 × 말하기 켜기/끄기의 90개 계획, 총 **117개** 원시 계획의 Float32 바이트·재질·셰이더 인자 일치 검사가 있습니다. 20개 효과 생성 규칙도 일치합니다. 외부 물리 상태, 작업 프로세스 종료·오류·시간 초과 후 폐기 검사도 포함합니다. 실행 전후 원본 런타임 JS **12개**, 실제 등록된 고유 PNG **3,077개**의 SHA256이 유지되었습니다.

최종 전체 pytest 실행은 종료 코드 0이며, **259개 테스트가 26.26초에 모두 통과**했습니다. 위 플래너 파일의 127개와 추가 키보드 메뉴 테스트는 이 전체 결과에 포함됩니다.

## 실제 OpenGL 검증 범위

[기존 네이티브 검증 보고서](../integration-validation/native/report.json)는 다음을 기록합니다.

| 검사 | 실제 확인한 범위 |
| --- | --- |
| 상태 조합 | 왼쪽·정면·오른쪽 × 9동작 × 15감정 × 말하기 켜기/끄기 = **810개** 실제 프레임버퍼 렌더링 |
| 조합의 대표 시점 | 동작 `time=0.76`, 음성 `speechTime=0.91`, 동반 캐릭터 켜기 |
| 연속 프레임 및 캐시 교체 | 좌우 인사 0~4.6초, 20fps, 각 93시점을 두 번 순회 |
| 저장된 원본/네이티브 비교 | 좌우 각각 0, 0.34, 0.38, 0.63, 0.76, 0.91, 1.25, 1.8, 3.5초 = **18장** |
| 실제 총 렌더 수 | 초기 화면 등을 포함해 **1,202프레임** |
| 기록된 오류 | 없음 |

810개 조합은 위 대표 시점에서 렌더링 오류와 캐시 동작을 확인한 범위입니다. 모든 동작의 전 구간을 영상으로 육안 검사한 수치가 아닙니다. 원본과 화면의 수치 비교는 실제 저장된 비교 프레임에 대해 수행했습니다.

추가로 [동기화 증거 보고서](../integration-validation/native/proof-v30/proof-report.json)는 **좌우 각 93장, 총 186장**의 새 Qt 프레임버퍼를 같은 v30 WebGL 시점과 비교했습니다. 해당 기준 캡처에 기록된 JS/등록 정보 7개 해시도 현재 파일과 모두 일치합니다. 이 작업은 브라우저를 실행하거나 다른 앱 화면을 캡처하지 않고, 고정 상태의 `QOpenGLWidget.grabFramebuffer()`로 렌더링했습니다. 원본 720×1080 PNG에 대한 수치 비교와 확대 자료 제작을 분리했습니다.

위 186장 결과는 당시의 전체 비교 기록입니다. 저장소에는 대표 원본·네이티브 이미지 각 18장과 비교 PNG·GIF·보고서를 포함합니다. 대량 연속 캡처, 전체 원본 메타데이터, 전체 GIF 생성 스크립트는 로컬 보관 폴더의 `commit-preparation/`에 보존했습니다. 저장소의 `capture-metadata.json`은 원본의 출처·시점·해시와 대표 시점을 추린 정보입니다. 아래 검증 명령은 저장소에 포함된 18장의 원본과 비교하고 810개 상태 및 연속 인사 렌더링을 검사하므로 보관 폴더 없이 실행할 수 있습니다.

비교는 투명 픽셀의 보이지 않는 RGB를 제외하기 위해 RGB에 알파를 곱한 RGBA를 사용합니다. 새 186장 중 채널 차이가 8/255를 넘는 픽셀의 최댓값은 왼쪽 2.20초의 **87/777,600픽셀, 0.0112%**입니다. 어느 프레임에서도 RGB 평균 절대 차이는 8비트 값 기준 **0.079**를 넘지 않았고, 알파 평균 차이는 **0.0184** 이내였습니다. 기존 18장은 최대 76픽셀이었습니다. 따라서 원화·구조·위치가 같은 화면임을 확인했지만, 서로 다른 WebGL/Qt OpenGL의 가장자리 래스터 처리까지 PNG 바이트가 완전히 같다고 주장하지 않습니다.

## 확대 비교 자료

각 이미지의 왼쪽 열은 실제 v30 WebGL 기준, 오른쪽 열은 네이티브 Qt이며, 위 행은 왼쪽 방향, 아래 행은 오른쪽 방향입니다. 팔 전체·긴 민트 줄·구름 로고·상단 고리·검은 하드웨어·손이 함께 보이도록 두 엔진에 같은 좌표를 적용했습니다. 화면 크기 확대와 배경 합성 외에 원본 그림을 고치지 않았습니다.

- [0.76초 좌우 확대 PNG](../integration-validation/native/proof-v30/arms-0760.png)
- [전신 0.76초 비교](../integration-validation/native/proof-v30/full-body-0760.png)
- [시작·전환·유지·복귀 연속 비교](../integration-validation/native/proof-v30/held-return-contact-sheet.png)

GIF는 파일 크기를 줄인 **10fps 미리보기, 47프레임, 256색**입니다. 원본 비교 PNG는 **20fps, 186장**이며, 픽셀 비교 결과는 GIF의 색상 축소 결과를 사용하지 않았습니다.

## 메모리 수치의 의미

**32MiB는 GPU에 동시에 남는 텍스처 픽셀 데이터의 캐시 예산입니다. 전체 앱 메모리 상한이 아닙니다.** GPU 드라이버 부가 비용, Qt 화면/프레임버퍼, Python 객체, Node/V8 메모리 등은 이 예산에 포함되지 않습니다.

| 항목 | 전체 상태 검증에서 실측 |
| --- | ---: |
| GPU 텍스처 예산 | 33,554,432 bytes = 32MiB |
| GPU 텍스처 최대 픽셀 데이터 | 33,553,680 bytes, 예산 이내 |
| GPU 텍스처 업로드 / 퇴출 | 1,477 / 1,251회 |
| 정점 버퍼 | 294,912 bytes |
| 한 번의 이미지 디코드 최대 픽셀 데이터 | 383,152 bytes |
| 별도 V8 작업 프로세스 RSS | 76,972,032 bytes ≈ **73.4MiB** |
| V8 사용 중 힙 | 15,727,904 bytes ≈ 15.0MiB |

추가 186장 비교 작업에서는 V8 RSS가 66,113,536 bytes, 약 63.1MiB였습니다. 두 RSS는 각각 보고서 시점의 값이며 프로세스 평생 최고치나 전체 앱 합계가 아닙니다. Node의 힙 옵션도 전체 프로세스 RSS 제한으로 해석하면 안 됩니다. 원본 가용 텍스처 목록과 GPU 캐시를 구분해, 캐시에서 퇴출된 이미지가 다음 동작의 재질 선택을 바꾸지 않도록 했습니다.

810개 상태에서 계획 계산 시간은 중앙값 **9.48ms**, 95백분위 **25.98ms**, 최대 **42.13ms**였습니다. 이 수치는 원본 JS 계획 생성이며, Qt 이벤트 처리·합성·오디오 등을 포함한 앱 전체 프레임 시간은 아닙니다.

## 실제 데스크톱 창 확인

새 코드를 실행한 실제 `main.py` 데스크톱 창에서 네이티브 Cloudy가 보이고 디버그 글씨가 표시되지 않는 것을 확인했습니다. 같은 실제 `CharacterWidget`을 사용하는 [호스트 검증 실행 파일](../integration-validation/native/preview-host-ui.py)에서는 검증 세션 동안 외부 AI·카메라·창 모니터만 중지하고, 캐릭터 렌더러·입력 처리·기분·중력 로직을 그대로 사용했습니다.

[생각 상태 기록](../integration-validation/native/host-ui-thinking-observations.json)의 2,703개 샘플은 0.281~295.875초 동안 수동 `thinking` 상태와 `moving=false`를 유지했습니다. [수면·드래그 기록](../integration-validation/native/host-ui-sleep-drag-observations.json)에서는 수면 상태를 122.062초까지 유지한 뒤 실제 마우스로 드래그했고, 놓은 뒤 `fall → land → idle` 전환을 기록했습니다. 착지한 캐릭터의 전신 화면도 확인했고, 319.312초의 마지막 샘플은 지면 위 `idle` 상태입니다. 두 기록의 모든 샘플에서 네이티브 렌더러가 유지되었고 디버그 표시가 꺼져 있었습니다.

Qt 팝업 메뉴가 화면에 표시되는 것은 확인했습니다. 하위 메뉴로 입력을 전달하지 못해 **실제 메뉴 선택 검증은 완료하지 못했습니다**. `Shift+F10` 경로는 단위 테스트를 통과한 범위이며 실제 데스크톱 메뉴 선택까지 확인한 결과로 해석하지 않습니다.

실제 `main.py` 실행에서 기존 perception receiver의 `WinError 10013`이 발생했고 이 문제는 별도로 남아 있습니다. 이 오류가 발생한 실행에서도 캐릭터 네이티브 렌더링은 정상으로 확인했습니다.
