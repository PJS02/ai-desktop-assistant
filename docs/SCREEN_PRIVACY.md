# 활성 창 개인정보 마스킹

현재 활성 창을 캡처하고, 기기 안에서 개인정보를 가린 뒤 기존 Gemini 멀티모달 API에 전달합니다.
캐릭터의 자동 활동 반응, `generate_dialogue_json()`, `python -m context.active_window_classifier`에 적용됩니다.
직접 입력·음성 대화는 기존처럼 텍스트 요청으로 동작합니다.

## 처리 순서

1. Pillow `ImageGrab`과 Windows 활성 창 좌표로 현재 창을 캡처합니다. 음수 좌표의 보조 모니터도 지원합니다.
2. PaddleOCR 3의 `PP-OCRv5` 한국어 모델이 텍스트·좌표·인식 신뢰도를 추출합니다. 화면 좌표가 바뀌지 않도록 문서 회전·왜곡 보정은 끕니다.
   Windows의 Paddle oneDNN/PIR 호환성 오류를 피하도록 CPU MKL-DNN 가속도 끕니다.
   Paddle CPU 추론이 GUI의 GIL을 점유하지 않도록 재사용하는 별도 로컬 프로세스에서 실행하며, CPU 스레드는 2개로 제한합니다. 탐지·한국어 인식 모델과 이미지 해상도는 유지합니다.
3. Microsoft Presidio의 `AnalyzerEngine`에서 카드·IP 탐지기, 한국어 `PatternRecognizer`, 한국어 이름 NER 탐지기를 실행합니다.
   이름 탐지기는 로컬 `Leo97/KoELECTRA-small-v3-modu-ner`의 인명(`PS`) 결과 중 신뢰도 0.70 이상을 사용합니다. 라벨 없는 이름과 문장 속 이름도 분석합니다.
4. 텍스트의 문자 위치를 OCR 상자에 다시 연결합니다. 숫자가 여러 상자로 나뉜 경우 공백을 제거한 탐지 결과도 원래 위치로 복원합니다.
5. PaddleOCR의 `return_word_box=True`로 단어 좌표를 받고, OpenCV로 개인정보가 걸친 **단어 상자**에 여백을 더해 검은색으로 덮습니다.
   단어 좌표가 개인정보 전체를 포함하지 못하면 해당 줄 전체를 가립니다. 글자 수로 좌표를 임의 추정하지 않습니다.
6. 창 제목·URL이 들어 있는 프롬프트와 시스템 지침도 탐지하고 `[REDACTED]`로 치환합니다. 화면의 `성명` 등에서 탐지한 이름은 제목에 라벨 없이 등장해도 제거합니다.
7. `ai/gemini_client.py`의 공통 전송 함수가 이 과정을 통과한 이미지만 메모리에서 PNG·Base64로 변환해 전송합니다. 이미지 요청 호출자가 마스킹을 생략할 수 있는 옵션은 없습니다.

## 탐지 범위

- 주민등록번호·외국인등록번호 형태, 국내 휴대전화·일반전화·`+82` 번호
- 이메일, 카드번호, IP 주소, URL 전체
- 여권·운전면허번호 형태, 하이픈으로 구분된 계좌번호 형태, 10–19자리 숫자
- 한국어 NER가 인명으로 판정한 라벨 없는 이름·문장 속 이름과, `성명:`, `이름:`, `예금주:`처럼 명시적 구분자가 있는 필드의 한국어 이름
- 주소 라벨 뒤 내용과 주요 시·도 및 도로명 주소 형태
- 계좌·카드·생년월일·아이디·비밀번호·API 키·인증번호 등의 라벨 뒤 내용

실제 개인정보를 놓치지 않도록 일부 번호는 체크섬 유효성에 관계없이 가립니다.
Presidio의 NLP 엔진에는 spaCy 다국어 기본 토크나이저를 연결하고, `KoreanPersonRecognizer`가 한국어 NER 결과를 Presidio의 `PERSON`으로 변환합니다.
NER의 일반 장소·조직·인공물 분류는 개인정보로 취급하지 않습니다. 주소와 정형 번호는 기존 규칙이 담당합니다.
`이름 변경` 같은 메뉴를 이름 필드로 취급하지 않도록 이름 규칙에는 구분자를 요구합니다. `비밀번호 변경`·`아이디 찾기` 같은 일반 UI 동작은 비밀값으로 취급하지 않습니다.
긴 입력은 겹치는 토큰 구간으로 나누어 분석합니다. 모델 가중치는 safetensors로 읽고 원격 사용자 코드는 실행하지 않습니다.

## 실패 처리와 저장

- OCR 신뢰도가 낮다는 이유만으로 가리지 않습니다. 텍스트가 비어 있는 영역·아이콘·인식 결과가 없는 영역도 개인정보 판정 없이 가리지 않습니다.
- OCR 신뢰도가 낮아도 읽힌 전화번호·이름 등을 개인정보로 판정하면 가립니다. 번호는 공백을 제거한 결과도 검사하지만 NER에는 원문 문맥을 유지합니다.
- 의존성·OCR/NER 모델 로딩·추론·탐지 실패, 결과 누락·개수 불일치·잘못된 좌표가 있으면 **HTTP 요청 전체를 차단**합니다. 원본 전송이나 제목만 전송하는 방식으로 우회하지 않습니다.
- 정상적인 OCR 결과에서 탐지된 텍스트가 하나도 없으면 그대로 진행합니다. OCR 자체가 놓친 글자는 별도로 검출하지 못합니다.
- 앱은 원본 캡처·OCR 텍스트·마스킹 이미지 파일을 저장하지 않습니다. 요청 로그에서도 이미지 Base64를 제외합니다.
- OCR 오류 메시지에 입력 내용이 섞일 수 있어 외부로 내보내는 오류에는 해당 메시지를 포함하지 않습니다.
- 모델은 첫 이미지 요청 때 초기화하고 재사용합니다. 잠금으로 여러 작업 스레드의 동시 모델 접근을 막습니다. GUI 자동 활동 반응은 기존 작업 스레드에서 실행합니다.
- OCR 이미지와 필요한 인식 결과만 로컬 프로세스 간 메모리 파이프로 주고받습니다. OCR 오류·프로세스 종료·120초 응답 초과 시 전송을 차단하고 해당 프로세스를 정리합니다. 다음 요청은 새 프로세스로 재시도하며, 앱 종료 시에도 자식 프로세스를 정리합니다.

## 설치와 실행

기존 앱 환경에서 다음을 실행합니다.

```powershell
python -m pip install -r requirements.txt
python main.py
```

처음 화면을 처리할 때 PaddleOCR의 탐지·한국어 인식 모델과 한국어 이름 NER 모델을 내려받습니다. NER 가중치는 약 56MB이며 PyTorch·Transformers가 필요합니다.
모델 다운로드가 가능한 인터넷 연결과 모델 캐시 디렉터리 쓰기 권한이 필요합니다. 이후 OCR·개인정보 탐지는 로컬에서 실행되며 화면·OCR 텍스트를 모델 제공자에게 전송하지 않습니다.
AI 설정에는 이미지를 지원하는 Gemini 모델을 지정해야 합니다. API 키와 모델 설정 경로는 기존 `ai/config/gemini_config.json`입니다.

## 검증

실제 활성 창의 마스킹 결과를 미리보기 창에서 확인하려면 다음을 실행하고 3초 안에 캡처할 창을 선택합니다.
Esc·Q 또는 닫기 버튼으로 종료합니다. 이미지는 메모리에서만 표시하며 LLM 요청과 파일 저장은 하지 않습니다.

```powershell
python preview_screen_privacy.py
```

특정 이름이 계속 누락되면 기존 미리보기를 닫고 다음처럼 실행합니다. 3초 안에 실제 메신저 창을 선택하세요.

```powershell
python preview_screen_privacy.py --check-name "김민수"
```

이름 자체나 OCR 원문을 출력하지 않고, 해당 캡처에서 이름의 OCR 일치 횟수·공백을 무시한 일치 횟수·이름 전체가 개인정보로 판정된 횟수만 출력합니다.
OCR 일치가 없으면 인식 단계의 문제이고, OCR 일치는 있지만 개인정보 판정이 없으면 탐지 단계의 문제입니다.
진단 자료는 메모리에서만 전달하며 파일·로그·LLM에 저장하거나 전송하지 않습니다. 미리보기는 실행 시 한 번 캡처하는 정지 화면입니다.

```powershell
python -m pytest tests/test_screen_privacy.py -p no:cacheprovider
```

기본 테스트는 실제 Presidio·OpenCV에 고정 OCR·NER 결과를 넣어 한국어 탐지, 여러 상자에 나뉜 번호, 아이콘·메뉴 보존, 단어 단위 마스킹, 좌표 검증, RGB 보존, 원본 불변, HTTP 이미지·프롬프트, 로그 제외, 실패 시 전송 차단을 검증합니다.

Windows의 맑은 고딕으로 만든 가상 화면에 실제 PaddleOCR를 실행하는 테스트도 있습니다. 실제 화면과 Gemini 서버에 접근하지 않습니다.

```powershell
$env:RUN_PADDLE_OCR_TEST = '1'
python -m pytest tests/test_screen_privacy.py -k real_paddleocr -p no:cacheprovider
```

실제 NER로 이름·일반 메뉴·긴 입력을 검사하고, 실제 OCR와 NER를 결합한 가상 화면에서 이름 마스킹과 아이콘·메뉴 보존을 검사하려면 다음을 실행합니다.

```powershell
$env:RUN_PADDLE_OCR_TEST = '1'
$env:RUN_KOREAN_NER_TEST = '1'
python -m pytest tests/test_screen_privacy.py -k real_ -p no:cacheprovider
```

## 한계

OCR가 글자를 탐지하지 못하거나 개인정보가 다른 문자로 오인식되면 마스킹이 누락될 수 있습니다.
NER도 오탐·누락이 가능합니다. 특히 별명·영문 이름·문맥 없는 짧은 이름의 탐지는 보장하지 않습니다.
OCR가 텍스트를 읽지 못한 영역은 자동으로 가리지 않으므로 개인정보가 남을 수 있습니다.
규칙 밖 주소와 얼굴·사진·QR 코드 같은 비텍스트 개인정보는 보장하지 않습니다.
OCR가 여러 한국어 단어나 아이콘을 같은 상자로 묶거나 단어 좌표가 부족하면 주변 일반 정보도 함께 가려질 수 있습니다. CPU OCR·NER로 화면 요청 지연이 늘어납니다.
이 기능은 화면 이미지 요청에 적용되며, 기존 텍스트 전용 대화·메모리·로컬 활동 메타데이터의 전체 개인정보 정리 기능은 아닙니다.

구현에 사용한 공식 API 문서: [PaddleOCR OCR pipeline](https://www.paddleocr.ai/main/en/version3.x/pipeline_usage/OCR.html), [Microsoft Presidio analyzer](https://microsoft.github.io/presidio/analyzer/).
이름 모델의 학습·평가 설명: [KoELECTRA 한국어 NER 모델 카드](https://huggingface.co/Leo97/KoELECTRA-small-v3-modu-ner). 해당 모델의 평가 수치는 본 프로젝트 화면에서의 개인정보 탐지 성능이 아닙니다.
