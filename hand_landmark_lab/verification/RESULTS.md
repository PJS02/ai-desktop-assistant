## 이전 버전: 좌표 튐 및 이전 손 그림 잔상 보완

- 사용자 제보: 이동 중 손 위치가 튀고, 첨부 사진에서 여러 이전 자세가 겹쳐 보임.
- 해당 손 앱의 실행 프로세스를 확인했으며 한 실행의 가상환경 런처/실제 Python 자식 쌍이 확인됨. 여러 독립 앱 실행은 발견되지 않음.
- 기존 코드의 큰 위치 변화 시 보정 생략, 순간 인식 끊김 시 이력 삭제, 창 크기 매 프레임 변경을 수정.
- `HandSmoother`: 안정된 손 ID, 잠깐의 좌우 판별 변화/두 손 검출 순서 변화 대응, 단일 큰 이상 좌표 거르기, 연속된 정상 큰 이동은 보간해 따라감, 0.12초 이내 인식 끊김 보완, 시간 간격에 따른 적응형 위치/손 모양 보정.
- `DesktopHandWindow`: 약 60회/초 표시 보간, 2 논리 픽셀 이내 중심 흔들림 억제, 창 크기 블록 할당 후 유지, 매 프레임 새 투명 이미지 생성.
- Windows 출력은 Qt 투명 창의 backing-store 대신 소유한 Win32 layered window의 전체 프레임을 `UpdateLayeredWindow`로 교체. 같은 프레임의 위치/크기/투명 픽셀을 함께 전달. Qt는 제어창/표시창과 벡터 그리기에 계속 사용.
- unittest 13개 통과. 큰 단일 오류 억제/정상 빠른 움직임 추종/짧은 인식 끊김 및 오래된 좌표 해제/좌우 판별 변화/보정 끄기 등을 포함.
- 정지 상태의 합성 ±0.008 잡음 검사: 표준편차 0.008 → 0.001224, 84.7% 감소. **합성 검사 수치이며 실제 카메라에서 같은 감소율을 보장하지 않음.**
- UI 검사: 이전 자세의 불투명 픽셀이 새 자세에서 투명해짐, native DIB의 모든 바이트가 새 프레임과 일치, 반복 이동 중 창 크기 유지, 실제 native HWND가 종료 시 파괴됨, 기존 이동/두 손/모드/닫기 검사 통과.
- 카메라 2 · DirectShow, 전체 손 모델 검사: 실제 손 최대 1개 검출, 141프레임, 표본 23.8 FPS, 마지막 추론 63.0ms, 작업 스레드 중지 확인. 기존 경량 모델보다 인식 연산량이 늘어날 수 있음. FPS는 실제 화면의 입력-표시 지연 측정이 아님.

```json
{"camera": 2, "backend": "dshow", "frames": 141, "fps": 23.8, "inference_ms": 63.0, "max_hands": 1, "worker_stopped": true, "error": ""}
```

남은 사용자 확인: 첨부 사진의 실제 바탕화면 잔상이 없어졌는지, 실제 손을 움직일 때 튐과 추가 지연이 허용 가능한지. 자동 검사만으로 이 시각적 문제의 최종 해결을 선언하지 않음.
